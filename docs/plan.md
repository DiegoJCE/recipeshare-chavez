# RecipeShare: build plan

One step at a time, in order. Tick a step off (`- [x]`) only when it works. Must features M1-M7 first; Should features only after M1-M7 work on the live app.

- [x] 1. Scaffold a runnable Next.js App Router (JavaScript) app with Vitest: package.json scripts (dev, build, start, test), lib/constants.js with the fixed CUISINES and CATEGORIES lists from the spec, lib/data.js with in-memory sample data (2 recipes, different cuisine and category, each with an image URL and ratings array) exposing getRecipes/getRecipe/addRecipe/addRating, and a home page that lists recipe titles; `npm run dev`, `npm test` and `npm run build` all succeed (files: package.json, next.config.mjs, vitest.config.mjs, jsconfig.json, app/layout.js, app/page.js, app/globals.css, lib/constants.js, lib/data.js, lib/constants.test.js; test: lib/constants.test.js checks the cuisine and category lists exactly match the spec)
- [x] 2. MANUAL: Deploy early to Vercel. Make sure the repo is pushed to GitHub, then go to https://vercel.com/new, sign in with GitHub, click "Import" next to the recipeshare repository (click "Adjust GitHub App Permissions" first if it is not listed), leave Framework Preset as "Next.js" and all other settings as default, click "Deploy", wait for "Congratulations!", click "Continue to Dashboard" and copy the live URL shown under "Domains" (files: none; test: open the live URL and see the 2 sample recipe titles)

M1: Show recipe cards on the home page with photo (plain img from the image URL), title, cuisine, category and average rating with rating count; put average calculation in lib/ratings.js (averageRating returns 0 for no ratings, rounded to 1 decimal); mark the home page dynamic (files: lib/ratings.js, components/RecipeCard.js, app/page.js, app/globals.css, lib/ratings.test.js; test: lib/ratings.test.js covers empty ratings, a single rating and a mixed list rounding to 1 decimal)

- [x] 5. M3: Add /recipes/new with a form (author name, title, cuisine and category as drop-downs from lib/constants.js, ingredients textarea, steps textarea, prep time minutes number, image URL) submitted through a server action; put validation in lib/validate.js (validateRecipe returns an errors object naming each missing/invalid field: empty required fields, prep time not a positive whole number, cuisine/category not in the fixed lists, image not an http(s) URL); on errors nothing is saved and each missing field is shown next to its input; on success redirect to the home page where the new recipe appears; add an "Add recipe" link in the header (files: app/recipes/new/page.js, app/recipes/new/actions.js, components/RecipeForm.js, lib/validate.js, lib/data.js, app/layout.js, lib/validate.test.js; test: lib/validate.test.js checks a full valid recipe has no errors, each empty required field is reported by name, and a cuisine outside the list is rejected)
